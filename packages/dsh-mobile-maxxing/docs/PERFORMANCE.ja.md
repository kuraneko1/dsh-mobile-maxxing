# 表示・読み込みの軽量化（v1.0.8 以降）

動作は変えずに、スマホでの表示処理と読み込みを軽くした記録です。省アニメーションのような「軽量モード」ではなく、
通常の動作そのものの無駄を削っています。

## 何が重かったか

長いセッション（12往復・約8,000要素）を iPhone 相当の画面と CPU 4倍低速で開き、実 UI から送信して返答を
ストリーミングさせて測りました（測り方は末尾）。

- **返答のストリーミング中に、毎チャンクで会話全体（約8,000要素）のスタイル再計算が走っていた。**
  上流（DSH 本体）の会話列の CSS が `:has()` を使っているため、1チャンクごとに会話全体が無効化される。
  プラグインは自前の `html:has()` ルール2つと `[class*=…]` セレクタでこれを悪化させ、1回あたり
  180ms → 270ms、回数もほぼ倍になっていた。
- **装飾パスが毎回ドキュメント全体を走査していた。** 約40個の装飾関数がチャンクごとに
  `document.querySelectorAll` を呼び、いくつかは `getBoundingClientRect` / `innerWidth` / `visualViewport`
  の読み取りで強制レイアウトを起こしていた。
- **`markScrollers` が約1秒ごとに全 `div` の `getComputedStyle` と `scrollHeight` を読んでいた。**
- **セーフエリア計測が毎回 `<body>` に要素を挿入・削除していた。** これ自体がプラグインの
  MutationObserver を起こし、装飾パスを1回余計に走らせていた。
- **Service Worker がキャッシュへの書き込み完了まで HTML とアセットを返さなかった。**

## 変えたこと

### 画面外の会話をレンダリングしない

- 終わったターン（user / turn-process / assistant-step）に `content-visibility: auto` を付け、画面外の
  ターンのスタイル・レイアウト・描画をブラウザに省かせる。
- 上流はスクロールアンカーを切って自前でスクロール位置を管理しているため、スキップ中のターンの高さが
  少しでも違うと表示が跳ぶ。そこで **一度描画されて実寸が記憶された（`contain-intrinsic-size: auto`）
  ターンだけ** を次のパスでスキップ対象にする。幅や文字サイズが変わったら全ターンを一度描き直してから
  再びスキップする（ResizeObserver）。
- 進行中のターン（最後の user 以降）は対象外。画面外で変化した内容が、戻ったときに跳びとして出ないように。
- turn-tail（操作ボタン行）は 6px はみ出すため対象外（paint containment でボタン背景が欠ける）。

### 装飾パスを減らす・軽くする

- Markdown 本文の中で、ボタン・リンク・画像・ラベル付き要素などを含まない変化（段落・リスト・表のセル・
  シンタックスハイライトの span）では、ドキュメント全体を見る速い装飾パスを走らせない。
- `markScrollers`：要素ごとの overflow を class / style 属性をキーにキャッシュ。スキップ中のターンは走査しない。
- `fitVisualViewport`：キーボードが閉じていると判定済みなら、ビューポートのイベントが来るまで再計算しない
  （ビューポートの読み取りは強制レイアウトになる）。ダイアログの全体検索はキーボードが開いているときだけ。
- `measureSafeArea`：計測用の要素を使い回し、`<html>` のカスタムプロパティは値が変わったときだけ書く。
- 同じ値の `setAttribute` を毎パス書いていた箇所を、値が違うときだけ書くようにした。
- タップ領域（44px）の判定は、サイズ外と測った要素を class / style が変わるまで測り直さない。
  右パネルの閉じるボタンは DOM の条件を先に見てから矩形を読む。サイドバーの「More」探しは
  `textContent` で絞ってから `innerText` を読む（どれも強制レイアウトを避けるための並べ替えで、結果は同じ）。
- 取りこぼし防止：遅いパスは 900ms に1回の間引きの後、最後の変化のあとにも必ず1回走る。

### CSS

- 省アニメーションの `*` ルールは、設定が「控えめ / オフ」のときだけ別シートとして入れる（標準では0件）。
- ファイル検索の `::highlight()` も、ハイライト中だけ入れる。
- `[data-slot="conversation.composer"] *` は、上流が変数を定義する `_body` / `_embeddedBody` だけに絞った。
- `html:has(...)` 2つは、JS が `<html>` に付ける属性に置き換えた（どこかに要素が挿入されるたびに
  `<html>` が全体を検査し直していた）。

### Service Worker

- ナビゲーションはネットワークを先に開始し、シェルのキャッシュ書き込みは `waitUntil` で裏で行う。
  Navigation Preload を有効にし、SW の起動とリクエストを並行させる。
- 初回取得の静的ファイルも、キャッシュ書き込みと件数整理を待たずに返す。

## 結果

iPhone 相当（390×844）・CPU 4倍低速・12往復のセッション。stock（プラグインなし）/ v1.0.8 / 変更後を
交互に3回ずつ回した中央値です（変更後は凍結コピーで計測）。

| | stock | v1.0.8 | 変更後 |
| --- | --- | --- | --- |
| ストリーミング：フレーム数 | 190 | 85 | **433** |
| ストリーミング：Long Task 合計 | 8.7秒 | 11.7秒 | **4.2秒** |
| ストリーミング：スタイル再計算 | 6.9秒 | 9.4秒 | **3.5秒** |
| ストリーミング：最長フレーム | 350ms | 1117ms | **300ms** |
| スクロール：Long Task 合計 | 1.8秒 | 3.2秒 | **1.1秒** |
| スクロール：スタイル再計算 | 1.2秒 | 2.1秒 | **0.24秒** |
| コールドロード：操作可能まで | 4.10秒 | 4.70秒 | 4.43秒 |
| 再読み込み：操作可能まで | 2.44秒 | 2.72秒 | 2.60秒 |
| 再読み込み：転送量 | 599KB | 31KB | 31KB |
| 待機10秒：メインスレッド | 0.79秒 | 0.80秒 | 0.83秒 |

- ストリーミングとスクロールは、プラグインなしの素の DSH より軽い。画面外の会話を描かないため。
- 読み込みは v1.0.8 より速いが、stock よりはまだ 0.2〜0.3秒遅い（プラグイン自身の起動と装飾）。
  コールドロードの転送量 5.2〜5.5MB のほとんどは上流の同梱ファイル（最大のもので gzip 後 4.2MB）。
- ストリーミング中の Script 時間が増えて見えるのは、フレーム数が 5倍になり上流の描画が細かく回るため。
  Long Task（操作をふさぐ時間）は 11.7秒 → 4.2秒に減っている。

## 測り方

上の数値は次の条件です。

- 使い捨ての DSH ホーム（既存の `~/.dsh` は使わない）にプラグインだけを入れた profile を作り、
  ローカルのモック LLM（OpenAI 互換、20ms ごとに約3トークン）をつなぐ。外部 API は呼ばない。
- 実 UI から12往復を送って長いセッションを作り、そのスナップショットを毎回戻してから測る。
- 実 Chrome（headless）で iPhone の UA・390×844・DPR 3・タッチ、CPU 4倍低速。
- フェーズ：コールドロード、リロード、待機10秒、スクロール（実スクロール）、ストリーミング1回（約6,000字）。
- Performance.getMetrics、Long Task、フレーム間隔、CPU プロファイル（ネイティブ DOM 呼び出しは呼び出し元の
  JS 関数に計上）。stock（プラグインなし）/ v1.0.8 / 変更後を交互に3回ずつ回し、中央値を取る。
- 画面外スキップの確認：同じスクロール位置のスクリーンショットを v1.0.8 と比較し、スクロール位置・高さが
  一致し、ピクセル差がないこと（文字のサブピクセル差のみ）を確認。
- ストリーミング中の DOM 変化は125バッチ中108バッチが会話ターンの中だけで、外側の変化は送信直後と完了時の
  入力欄・新しいターンの追加に限られる。Markdown 本文だけの変化で全体パスを省いても、ヘッダーやパネルの
  装飾が遅れることはない。
- headless Chrome の合成タッチはスクロールしない（stock でも同じ）ため、スクロールはマウスのスクロール
  ジェスチャーで測る。

実機（iPhone / Android）の体感は未確認です。Chrome の端末エミュレーションを実機の代わりにはしません。
